# Руководство

Быстрый запуск описан в [README](../README.md), выбор моделей — в
[MODEL_SELECTION](../MODEL_SELECTION.md), выполненные проверки — в [VALIDATION](VALIDATION.md).

## Установка и офлайн-работа

Нужны Python 3.13, uv и запущенная Ollama. Команды выполняются из `local_rag_service`.

```bash
uv sync --frozen --python 3.13
cp .env.example .env
uv run --frozen python prepare_models.py
ollama pull qwen3.5:9b
```

`prepare_models.py` скачивает BGE-M3, multilingual-E5-large, BGE reranker и модели
Docling. Ревизии Hugging Face и контрольные суммы сохраняются в `models/manifest.json`.
Можно закрепить ревизию: `--revision BAAI/bge-m3=COMMIT_SHA`.
После переноса весов выполните `uv run --frozen python prepare_models.py --verify`.

Приложение работает без скачивания весов и отклоняет облачные модели Ollama.
Для закрытого контура заранее подготовьте зависимости под ОС и архитектуру сервера;
окружение `.venv` с macOS переносить на Linux нельзя. Альтернатива uv — установка
`requirements.txt` через pip в виртуальном окружении Python 3.13. Обе спецификации
зависимостей сохранены для воспроизводимости. Ограничение `langchain-community<0.4.2`
нужно для совместимости с используемым Ragas.

## Настройки

Параметры читаются из `.env` и переменных окружения; относительные пути отсчитываются
от `local_rag_service`, а не от текущего каталога терминала.

| Параметр | Назначение / значение по умолчанию |
| --- | --- |
| `OLLAMA_BASE_URL` | Локальный адрес Ollama, `http://localhost:11434` |
| `DEFAULT_LLM_MODEL` | Модель ответов API/чата, `qwen3.5:9b` |
| `JUDGE_MODEL` | Судья экспериментов, `gemma4:31b` |
| `DEFAULT_EMBED_MODEL` | Эмбеддинги, `BAAI/bge-m3` |
| `DEFAULT_RERANKER_MODEL` | Реранкер, `BAAI/bge-reranker-v2-m3` |
| `DEVICE` | Устройство PyTorch-компонентов, `cpu` |
| `OLLAMA_TIMEOUT` | Тайм-аут запроса, 120 секунд |
| `OLLAMA_NUM_CTX` / `OLLAMA_NUM_PREDICT` | Контекст / бюджет ответа, 32768 / 2048 |
| `OLLAMA_KEEP_ALIVE` | Время удержания модели, `5m` |
| `SEED` | Seed генерации, 42 |
| `OCR_ENABLED` | OCR для PDF, по умолчанию выключен |
| `OCR_LANGUAGES` | Языки OCR, `["rus", "eng"]` |

Полный список путей и параметров — в [.env.example](.env.example).
Для OCR нужны установленный Tesseract и языковые пакеты. Автоматический OCR
изображений в PPTX не реализован. Объём RAM/VRAM зависит от весов и контекста;
наличие GPU само по себе не гарантирует совместимость сборки PyTorch.

На кластере Slurm и Ollama запускаются вручную на выделенном вычислительном узле.
В проверенном профиле V100 использовался `DEVICE=cpu` для PyTorch и GPU через Ollama.
В таком профиле время поиска включает вычисления CPU. Все LLM одновременно
скачивать или держать в памяти не требуется.

## Чат и API

Поместите документы в `data/raw`, затем:

```bash
uv run --frozen python chat.py --model qwen3.5:9b --ingest
```

`--ingest` нужен для создания индекса или после изменения документов.
`--question "Ваш вопрос"` выполняет один запрос, `--sources` показывает фрагменты,
`--models` выводит установленные модели, `--ollama-url` задаёт адрес Ollama.
В интерактивном режиме: `/model ИМЯ`, `/models`, `/ingest`, `/sources`, `/help`, `/exit`.
История переписки не передаётся модели.

```bash
uv run --frozen uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Схемы запросов и интерактивная документация доступны на `http://127.0.0.1:8000/docs`.

| Метод | Назначение |
| --- | --- |
| `POST /ingest` | Обработать документы и построить индекс |
| `POST /rag` | Ответить с найденными источниками |
| `POST /generate` | Ответить без поиска по документам |
| `GET /models` | Список локальных моделей |
| `GET /health` | Готовность сервиса и информация об устройствах |

При отсутствии индекса API возвращает 409, при некорректных данных — 422,
при тайм-ауте Ollama — 504. Сервис может стартовать без Ollama, но `/health`
вернёт 503. `REQUIRE_OLLAMA_ON_STARTUP=true` делает Ollama обязательной при старте.

## Индексация и поиск

PDF/DOCX/PPTX преобразуются Docling в Markdown; TXT/MD читаются напрямую.
Стратегия `naive` делит текст по размеру, `structural` учитывает разделы и таблицы.
Обе используют общий токенизатор E5 с резервом для заголовков и префиксов.
Слишком длинные строки таблиц и запросы отклоняются вместо скрытого усечения.

`dense` использует Chroma; `hybrid` объединяет его с BM25 через reciprocal rank fusion.
`hybrid_rerank` дополнительно ранжирует до 15 кандидатов. Генерация поисковых
запросов отключена: для самого поиска LLM не нужна.

Версии индексов, сохранённые фрагменты и контрольные суммы находятся в `data/indexes`.
Активная версия переключается после успешной сборки; прежняя остаётся при сбое.
Изменение моделей или повреждение сохранённых фрагментов требует переиндексации.
Запросы журналируются локально в `logs/queries.jsonl`.

## Эксперименты

`data/test_questions.csv` содержит обязательные поля:
`question_id`, `question`, `ground_truth_answer`, `expected_source_doc`.
ID должны быть уникальными, имена источников — путями относительно `data/raw`.

Подготовлены 90 вопросов по 15 PDF. Статус `expert_confirmed_user_reported`
отражает сообщение пользователя о проверке с преподавателями. Имена и дата проверки
не сообщены. Статус переносится в результаты. Локальные подтверждающие фрагменты,
страницы и SHA-256 PDF хранятся в `test_questions.evidence.csv`, читаемая версия —
в `QUESTIONS_DRAFT.md`; эти файлы и исходные лекции исключены из Git.

25 конфигураций: exp1 — 4 варианта чанкинга, exp2 — 5 вариантов поиска,
exp3 — 6 LLM × RAG/direct, exp4 — 2 эмбеддинга × top-3/top-5.
В exp3 фиксированы structural/512, BGE-M3 и hybrid_rerank/top-3.

Пример отдельного запуска одной модели:

```bash
uv run --frozen python experiments.py --experiment exp3 --models qwen3.5:9b --repeats 1 --phase generate --output-dir results/qwen9b
uv run --frozen python experiments.py --experiment exp3 --models qwen3.5:9b --repeats 1 --phase evaluate --resume --output-dir results/qwen9b
```

| Аргумент | Назначение |
| --- | --- |
| `--experiment` | `all`, `exp1`, `exp2`, `exp3`, `exp4` |
| `--model` | Базовая LLM для exp1/exp2/exp4, по умолчанию Qwen 3.5 9B |
| `--models` | Подмножество моделей exp3 |
| `--data-path` / `--output-dir` | Вопросы / отдельный каталог прогона |
| `--repeats` / `--temperature` | Повторы / температура, по умолчанию 3 / 0.1 |
| `--phase` | `generate`, `evaluate` или `all` |
| `--resume` | Продолжить сохранённый прогон |
| `--no-warmup` | Отключить отдельный прогрев |

Генерация требует выбранные LLM; оценка — только судью и сохранённые ответы.
Судья работает с temperature=0. Его digest и версия Ollama записываются отдельно
в `evaluation_manifest.json`; смешивание разных судей в одном прогоне запрещено.

Контрольные точки записываются после каждого вопроса. `--resume` повторяет ошибки,
сохраняет завершённые результаты и требует совпадения конфигураций, данных, кода
и окружения. Для изменённых входов нужен новый каталог. Одновременная запись
двух запусков в один каталог блокируется.

Результаты: `evaluation_results_raw.csv`, `summary_metrics.csv`, `plots/`;
параметры запуска — `run_manifest.json`, версии индексов — `index_versions.json`.

## Интерпретация результатов

- Hit Rate и MRR оцениваются на уровне документа; Hit@5 при выдаче менее 5 фрагментов — N/A.
- Faithfulness оценивает опору на контекст; для direct она N/A и не измеряет галлюцинации без RAG.
- Semantic Similarity — косинус BGE-M3 между ответом и эталоном, не доказательство правильности.
- Оценки судьи требуют выборочной ручной проверки, особенно для ответов его собственного семейства.
- Retrieval latency включает реранкинг; время реранкинга также записывается отдельно.
  Время судьи и прогрев не входят в задержку ответа. RSS — память процесса Python,
  а не пик VRAM или память Ollama. Одинаковый seed не гарантирует побитовую повторяемость.

## Проверки кода

```bash
uv run --frozen pytest -q
uv run --frozen ruff check .
```

Тесты не обращаются к внешней сети и не заменяют запуск на настоящих весах.
